# Customer Decision Framework (Four-Quadrant Decision Governance)

## 1. Executive Purpose
Security reports that merely report historical telemetry fail executive leadership. Every CloudShield report functions as an **executive decision instrument**.
Each monthly report must feature a dedicated decision section organized into four distinct decision states:

1. **Approved Decisions (Onaylanmış Kararlar):**
   - Actions proposed in previous cycles that were approved and completed.
   - Evidence of verified security improvement post-implementation.

2. **Pending Decisions (Bekleyen Kararlar):**
   - Critical configuration changes or exceptions currently awaiting customer C-Level/IT authorization.
   - Direct impact on security risk if authorization is delayed.

3. **Deferred Decisions (Ertelenmiş Kararlar):**
   - Acknowledged risks where the customer explicitly chose to defer action.
   - Documented risk acceptance with scheduled re-evaluation deadlines.

4. **Recommended Decisions (Önerilen Kararlar):**
   - Proactive architecture hardening recommendations generated by KoçSistem engineers based on the current month's telemetry.

---

## 2. Mandatory Schema for Recommended Decisions
Every recommended decision must contain the following five attributes without exception:

| Attribute | Definition | Example |
| :--- | :--- | :--- |
| **Decision ID** | Unique tracking reference | `DEC-2026-08-MDE-01` |
| **Recommendation** | Clear, non-technical executive proposal | Enforce BitLocker XTS-AES 256 hardware encryption on all executive laptops |
| **Owner** | Named customer role / RACI responsible | BT Altyapı Direktörü / CISO |
| **Priority** | Urgency classification | `Yüksek (P1)` / `Orta (P2)` / `Düşük (P3)` |
| **Evidence Source** | Telemetry / KQL / Audit provenance | `DeviceEvents` / Intune Hardware Telemetry (14 devices unencrypted) |
| **Expected Outcome** | Measurable security and compliance benefit | 100% sensor hygiene and zero data breach liability under KVKK md. 12 |
